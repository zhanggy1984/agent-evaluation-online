### 本轮最值得记的两条（都指向同一类错误）

**① 取证者污染自己的观测面（P1-15）。** `useMetricFilter` 把筛选状态写进 `localStorage` 并**跨页共享**，
subagent 在某页选了 `good-question` → 跳页看到仍是 `good-question` → 记成「默认值不一致」。
**他记的「默认值」根本不是默认值，是他自己上一步的操作。** 这是既有教训「**探针命中上一轮自造行**」的字面复现，
但**触发面比那条更宽**：那条说的是「探针命中上一轮自造行」，这条是**任何一个有持久化状态的前端，走查者看到的都不是首访状态**。
⇒ **判「默认值 / 初始状态」类断言，必须清 `localStorage` 后重开**；否则观测到的是历史，不是默认。

**② 被要求的东西已经在了（P1-14）。** 该条要求「补一行 `共 N 条（上限 M）`」，而**这行早就渲染着**，
且 `total` 用的是 `cardinality` 独立算的真实总数（不是 `items.length` 冒充的）—— 实现**比要求还严谨**。
**误报成因**：subagent 数了「50 行」就下结论「无总数」，**没有滚到底 / 没看见那行**。
⇒ **「无 X」型断言（无总数 / 无按钮 / 无排序 / 无 tooltip）是最脆弱的一类**：
它要求穷尽，而走查者看到的是**视野内**。本轮成立的 3 条（P1-6/8/18）之所以成立，
是因为我**回到源码做穷尽 grep** —— 不是因为他当时看见了。

## 十八、批 13（2026-09-19）：P2-23 修复 —— **代码改动 1 文件 + 真机复验**

### 一、改了什么

`frontend/src/components/TimeSeriesChart.vue`（唯一改动文件，模板 + `ticks` 计算属性）：

1. **主因（刻度贴脸）**：把 `ticks` 从「按 `step = floor(n/6)` 走网格，再**无条件**补 `n-1`」
   改成「**首尾必在、中间等分**」：`count = min(7, n)`，下标 = `round(k·(n-1)/(count-1))`。
   - 旧写法的病不在「补位」本身 —— 当 `n-1` 恰好是 `step` 的整数倍时它反而**不补**、刻度更少；
     病在 `(n-1) mod step` 很小时（本次 `n=123, step=20`，余 2）补位与末位网格点**只隔 2 桶**。
   - 等分生成让间距恒为 `(n-1)/(count-1)` 桶，**结构上不存在贴脸**，且不引入任何阈值常量。
     代价：刻度不再落在 `step` 的整数倍上（对读图无影响）。
2. **次因（同日重复标签）**：7d 的 `MM-DD` 粒度粗于 1 小时桶，等分后相邻刻度仍可能同日
   ⇒ **连续重复的标签只渲染第一个**；被跳过者**整个条目不产出 ⇒ 该处什么都不渲染**。
   ⚠️ **本节初稿写的是「`text` 置空、刻度位置留着、网格线不错位」，两句都错**（2026-09-19 预提交钩子复核时发现）：
   实现是 `continue` 整个条目，**没有元素留下**；且 `gridVals` 画的是**横向的 y 轴网格线**，
   **x 轴本来就没有网格线**，所以「错位」这个风险根本不存在。**实现未变，改的是描述。**
   `ticks` 的返回类型由 `number[]` 改为 `{ i: number; text: string }[]`，模板同步。

## 二十二、批 17（2026-09-19）：P1-6 收口 —— `/interfaces` 截断自陈 + 剩余面判不做

### 一、做了什么
